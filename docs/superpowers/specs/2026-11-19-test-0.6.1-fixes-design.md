# Test 0.6.1 – fixes for 0.6.2 (short design)

Source: user's test report of 0.6.1 (F1, F5, F6, F7, wish "Lupe"). Approved by the user on 2026-11-19.

## Intent
Finish the test phase: make the player and the overview behave the way the user expects, and make the Resolve
window show the real Resolve marker colours (some swatches looked alike under different names).

## Items
- **F5 – blue frame in the overview.** Today dragging the frame only pans the view; during playback the playhead
  stays where it was and auto-follow throws the view back. New: when a drag (moved > a few px) ends, the playhead
  goes to the time under the mouse at release (clamped to 0 … duration, so dragging past the left edge = start).
  Playing keeps playing from there; stopped just moves the playhead. A click on the frame without movement does
  nothing (keeps double-click intact). Double-click on the frame always plays from its left edge, playing or not.
  Exception (my call): with the loop "section" active the left edge stays the loop start; no seek on release.
- **F1 – song / metronome mute look.** Both rows: speaker toggle button (muted = VolumeX, grey, like today's
  metronome), own icon (note for song, pendulum metronome for metronome), label, slider. No red strike-through.
- **F6 – folded bar.** Order of the buttons as in the beat table: undo first, then reset.
- **F7 – Resolve window swatches.** `SWATCH_HEX` gets the colours of Resolve's own marker menu (user screenshot):
  Blue #007FE3, Cyan #00CED0, Green #00AD00, Yellow #F09D00, Red #E12401, Pink #FF44C8, Purple #9013FE,
  Fuchsia #C02E6F, Rose #FFA1B9, Lavender #A193C8, Sky #92E2FD, Mint #72DB00, Lemon #DCE95A, Sand #C4915E,
  Cocoa #6E5143, Cream #F5EBE1. Names unchanged.
- **Wish – default quick window.** Double-click on 5 s / 15 s / 30 s / 60 s makes it the default window applied
  when a song loads; shown bold. Double-click on the current default clears it. Stored in localStorage
  (try/catch, works without it).
- **Marker JSON BPM per marker:** unchanged (user decision).

## Approaches
Only one sensible way per item; each is a local change in the existing component (`WaveformBeatVisualizer`,
`PlayerControls`, `BeatEvidenceLab`, Resolve Lua). Alternatives considered for F5: moving the view to the click in
the big waveform too (rejected: content slides away under the mouse, breaks scrubbing and Shift/Alt editing);
seeking continuously during the drag (rejected: audio stutters while dragging).

## Left to the builder
Tests per item where testable (pure helpers), CHANGELOG, version 0.6.2, German test list.
